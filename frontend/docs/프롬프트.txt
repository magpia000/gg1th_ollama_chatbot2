1단계 — PRD 생성 프롬프트
너는 시니어 프론트엔드 아키텍트다. 첨부한 chat_ui_설계도.jpg를 기준으로
React 프론트엔드 PRD를 작성한다.

규칙:
1. 먼저 아래 항목에 대해 나에게 명확화 질문을 던져라. 질문 없이 바로 PRD를 쓰지 마라.
   - 화면/컴포넌트 단위 분해가 애매한 부분
   - 상태 관리 범위 (로컬 state vs 전역 state)
   - API 연동 여부와 데이터 스키마
   - 반응형 대응 범위
2. 내가 답변을 준 뒤에만 PRD를 작성한다.
3. React 관련 결정(버전, 훅 사용 패턴, 권장 라이브러리)을 내리기 전에
   반드시 context7을 사용해 최신 React 공식 문서를 확인하고, 그 근거를 PRD에 각주로 남겨라.
4. PRD는 다음 5개 섹션으로 마크다운 작성한다:
   프로젝트 개요 / 기능 요구사항(화면별) / 기술 제약(스택, 폴더 구조 고정) / 
   컴포넌트 트리 및 파일 구조 / 수용 기준(완료 판정 기준)
5. 폴더 구조는 반드시 명시적으로 고정해서 제시하라. 임의로 컨벤션을 만들지 마라.
6. 이 단계에서는 코드를 작성하지 않는다. PRD 파일(docs/frontend-prd.md)만 생성하고 멈춰라.

[사용 스택: React 19 + (예: Tailwind/CSS Modules) — 확정되면 채워 넣기]
- TypeScript를 사용하지 않는다

2단계 — 작업 목록 생성 프롬프트
docs/frontend-prd.md를 입력으로 받아 실행 가능한 원자적(atomic) 작업 목록을 생성한다.

규칙:
1. 먼저 상위 작업(parent task) 5개 내외만 제시하고 나의 승인을 기다려라.
   하위 세부 작업으로 바로 쪼개지 마라.
2. 내가 상위 작업을 승인한 뒤에만 각 상위 작업을 하위 작업으로 세분화한다.
3. 컴포넌트별 작업은 "설계도 상 어느 화면/영역에 대응하는지"를 각 작업 제목에 명시하라.
4. 각 하위 작업에는 해당 작업에서 사용할 React 훅/패턴이 있다면 
   context7로 최신 문서를 확인한 API 시그니처를 참고 링크 형태로 같이 적어라.
5. 결과는 docs/tasks.md 파일로 저장하고, 각 작업 앞에 체크박스([ ])를 붙여라.
6. 이 단계에서도 코드는 작성하지 않는다.

3단계 — 작업 처리 프롬프트 (TDD 기반)

tasks.md의 체크되지 않은 작업을 하나씩 순서대로 처리한다.

규칙:
1. 한 번에 하나의 하위 작업만 진행한다. 여러 작업을 동시에 처리하지 마라.
2. 작업 시작 전, 해당 작업에 필요한 React API/라이브러리 사용법을
   context7로 재확인하고 버전 불일치가 없는지 검증하라.
3. TDD 순서를 지켜라: 
   (1) 실패하는 테스트 작성 → (2) 최소 구현으로 테스트 통과 → (3) 리팩토링
4. 하나의 하위 작업이 끝나면 다음 하위 작업으로 자동으로 넘어가지 말고,
   결과를 요약해 보고한 뒤 내 승인을 기다려라.
5. 상위 작업에 속한 모든 하위 작업이 끝나면 해당 상위 작업의 체크박스를 체크하고
   여기서도 멈춰서 보고하라.
6. 설계도(chat_ui_설계도.jpg)와 실제 렌더링 결과가 다르다고 판단되면
   임의로 수정하지 말고 먼저 나에게 질문하라.
